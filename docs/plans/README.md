# Cryptoalegre Design Plans

These documents are draft specifications for public review. They record confirmed decisions, proposed enforcement mechanisms, security boundaries, delivery phases, acceptance criteria, and questions that still require constitutional ratification.

Nothing in this directory should be treated as a deployed contract, ratified policy, legal opinion, or final constitutional text.

## Plans

- [Membership System](membership-system.md) — Mainnet membership credentials, member states, one-member-one-vote governance, ENS member names, Safe authority, recovery, suspension, and revocation.
- [Unified Members Forum](unified-members-forum.md) — One shared multilingual forum, membership-gated access, translation, moderation, privacy, and the boundary between deliberation and binding governance.
- [Constitutional Enforcement](constitutional-enforcement.md) — Authority hierarchy, treasury spending proposals, policies, initiatives, voting mathematics, conflicts, timelocks, and the first restricted Treasury Vault implementation.

## Review status

All three plans are drafts. Before implementation or Mainnet deployment they require, as applicable:

1. Founding-member review.
2. Constitutional ratification of unresolved governance parameters.
3. Portuguese legal review against the Association's registered statutes and applicable law.
4. Independent smart-contract security review.
5. Testnet validation using the three founding memberships.
